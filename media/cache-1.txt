Proxies and cache hits

Trace a cache with room for two exhibit descriptions through accesses A, B, A, C, B. A and B initially miss and fill the cache. The second A is a hit and makes A the most recently used entry. C then misses and evicts B under least recently used eviction. The final B misses and evicts A. Only one of these five accesses hits, showing that a cache’s benefit depends on access order and capacity, not merely on its existence. In a managed cache design, application code performs this lookup and fill around storage access. With a caching proxy, the client uses its normal request interface while the intermediary manages eligible reuse. Both still need a valid key and freshness policy. A load-balancing proxy performs a different decision: which backend should receive work that must be forwarded? One component may implement both roles, but a diagram should make clear whether it is selecting a worker, serving saved content, or doing both.

Popularity, freshness and HTTP caching

Suppose an exhibit launch receives 800 eligible reads each second and the measured cache hit ratio is 85 percent. Under a simple model with one backing read per miss and no revalidation traffic, only 120 reads per second reach the backing service. This gain follows from repeated demand for reusable content. If requests become personalized or spread across many rarely repeated items, the same cache may achieve a much lower hit ratio. Freshness is a separate decision. A public exhibit description might tolerate a short stale interval, while a reservation confirmation needs a different policy. Versioned image names let old and new images coexist without changing an existing cache entry. For mutable responses, distinguish expiration, validation and storage prohibition. No-cache can allow storage but requires successful validation before reuse; no-store forbids storage. A private response cannot become a shared-cache answer simply because it has a long freshness lifetime. Always explain whose requests are allowed to reuse an entry.
