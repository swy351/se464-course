1. A subtype that rejects a valid client

A scheduling library exposes Notifier.send(message), whose documented contract accepts any nonempty message up to 1,000 characters. A new SMSNotifier implementation rejects messages longer than 160 characters, although existing clients may send 500-character messages. Which redesign best preserves the stated client contract while making the SMS limitation explicit?

  1. Keep the implementation because clients should know SMS limitations.
  2. Silently truncate all long messages.
  3. Rename SMSNotifier to FastNotifier without changing behavior.
  4. Use a narrower SMS capability or an adapter that fulfills the original delivery contract.

Each Catalog also owns layout Blocks that have no meaning outside that catalog. Describe UML relationships and multiplicities for both cases.
