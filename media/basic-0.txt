A scalable publishing system: the NGVM case
Part 1 • Synthetic narration

Read the case architecture and its interfaces

Use a hypothetical city history archive to practise reading a deployment diagram. A visitor requests a public exhibit page. The application reads descriptive records from a relational database, renders the page, and includes image URLs delivered through a media service. A curator uploading a replacement image follows a different path: authenticate the curator, check editing permission, store the object, and update its metadata. One diagram contains both paths, but their failure and permission requirements differ. Mark every crossing with the information it carries. The object store receives bytes, while the database receives identifiers, captions and relationships. The browser receives a presentation rather than unrestricted database access. If image storage succeeds but the metadata update fails, an unreferenced object can remain; if the metadata points at a missing object, the public page breaks. This small example makes interfaces concrete and exposes coordination questions before introducing more servers. Naming an endpoint after a resource helps readers, but does not settle these consistency or access-control obligations.


Place media, caching and operating cost in context

An archive has a two-megabyte photograph but displays a small preview in its search results. If one thousand searches each download the original, that is about two gigabytes of image transfer before protocol overhead. A forty-kilobyte preview reduces the same illustrative workload to roughly forty megabytes. Storing multiple representations spends some storage and processing to reduce repeated transfer. The relational record can identify each representation while object storage holds the bytes. Next distinguish a cache hit from an origin fetch. A media cache can reduce repeated origin work, but total cost still depends on the charging model for storage, requests and delivery. Build a worksheet with quantities first and insert current prices only when preparing an actual estimate. A historical cloud bill is evidence about one workload and configuration, not a promise for the archive. Private images also need a permission design: an unpredictable filename alone does not establish who may fetch an object.
