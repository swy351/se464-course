Load balancing
Part 1 • Synthetic narration

One service, many workers

A public archive adds three application workers behind one service address. With round robin, six incoming requests can be distributed two per worker. That sounds balanced until one request generates a large export while the others read a small record. Equal request counts do not imply equal work or equal completion times. A routing policy uses observable signals, and those signals are only approximations of the capacity each worker has available. Next ask whether workers are interchangeable. If an export’s progress exists only in worker A’s memory, sending a follow-up request to B may fail even though B is healthy. Durable progress in shared storage can allow replacement, but that storage now needs its own capacity and failure design. The balancer gives clients a stable entry point and can hide worker membership changes. It does not remove every dependency behind that entry point. Follow one request to storage and back before claiming that adding workers has multiplied end-to-end capacity.


Local routing: L4 and L7

The archive serves metadata and large scans through the same HTTPS hostname. If routing must distinguish /records from /scans, some component must inspect HTTP information. An ordinary IP-and-port decision cannot see that distinction inside encrypted application traffic. An HTTP-aware reverse proxy can terminate TLS, inspect the path and select an appropriate worker pool. It may establish a second encrypted connection upstream; termination does not require leaving the internal hop unprotected. For a generic transport service, a layer-four balancer may be a better fit because it routes using connection information without interpreting HTTP resources. NAT is one implementation, not the definition of layer-four balancing. Likewise, a reverse proxy need not wait for an entire document before forwarding it: streaming and buffering depend on implementation and configuration. Compare designs using the features required by this workload, then benchmark realistic payloads, connections and security settings. Historical throughput examples should not become universal limits for either layer.
