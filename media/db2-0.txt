Data locality and denormalization

Think of a relational dataset as a graph: rows are vertices and references are edges Partitioning tries to balance the data while cutting few frequently traversed edges. No. It can make profile reads local, but the rename now affects many copies or requires accepting temporary disagreement.

Hash partitioning

A deterministic hash maps a key to a value in a fixed hash space Partition owners can divide that space into ranges; a client or routing layer hashes a requested key and selects its owner. No. All requests for that key still map to its owner or replica set unless the application introduces another distribution or caching strategy.

Replication and partitions

Partitioning spreads different data across machines; replication stores multiple copies of each partition Replication allows a system to keep a copy when a machine fails, but a change reaches replicas at different times. Not while also remaining available for every request; they cannot coordinate the conflicting decisions across the partition.
