AI & the LEARN submission case
Worked answers

SE464 · Newly authored scenarios · Three exercises

1. What evidence supports the diagram?

An AI assistant generates a deployment diagram for a campus equipment-loan service. It draws separate reservation, payment and notification services. The team has only browser access and observes that reservation and notification fail together during an outage. Which review response is best supported by this evidence, before anyone has inspected source code or deployment configuration?

  1. Label the boundaries unverified and seek traces or deployment evidence.
  2. Replace all three services with one process because the failures coincide.
  3. Accept the diagram because independent services can fail together.
  4. Infer a shared database and mark that inference as confirmed.

Worked answer

Best answer: A.

The best response is to mark the service boundaries as unverified and propose further evidence. Two features failing together could share a process, storage dependency, network path or identity provider. Browser observations establish the visible failure pattern, not its cause. Keep the generated diagram as a hypothesis, label the observed behavior separately and ask for permitted traces or deployment configuration that can distinguish the alternatives. A polished diagram does not increase the strength of the underlying evidence.

Architecture recovery must distinguish observation from inference; several different implementations can produce the same visible result.

Check your work

  • Separates observed behavior from inferred topology
  • Identifies evidence that distinguishes competing explanations

2. Review a generated reconciliation change

A rental platform promises that one physical bicycle cannot be assigned to two active rentals. An AI-generated optimization checks availability in a read replica, then writes a rental to the primary. Sequential tests pass. Write a short architecture review: identify the promise at risk, propose a concurrent test, and describe a design constraint that would protect it. Do not assume the replica is current or that an extra pre-check is atomic.

Worked answer

The invariant is at most one active rental per bicycle. Start two requests for the same bicycle behind a test barrier so both availability checks complete before either write proceeds; introduce replica lag if needed. Assert that at most one request commits a rental. Enforce the invariant at the authoritative write boundary through an atomic conditional operation or suitable transaction and uniqueness mechanism. A second check outside that boundary still races. Record why the optimization was rejected or constrained and add the concurrent scenario to verification.

Architecture review evaluates a generated change against a system promise, rather than treating passing sequential tests as sufficient.

Check your work

  • States the cross-request invariant
  • Constructs a controlled concurrent failure test
  • Places enforcement at an authoritative atomic boundary

3. Recover missing decision rationale

A team inherits an AI-assisted document-conversion service with a twenty-megabyte upload limit. Nobody remembers why the limit exists. Product wants to raise it to two gigabytes tomorrow. Propose an evidence-gathering plan and a minimal decision record. Explain how you would distinguish an intentional architectural constraint from an arbitrary generated default without asserting that either explanation is already true.

Worked answer

Inspect configuration history, tickets, provider limits and permitted operational measurements, then trace how upload size affects buffering, conversion memory, duration and temporary storage. Run bounded experiments at increasing sizes and check cancellation and partial-file cleanup. The limit may protect a resource, satisfy a dependency or simply be a default; label these as hypotheses until evidence distinguishes them. Record the user need, alternatives, measured constraints, chosen limit and review trigger. A larger limit should follow an explicit streaming or resource-management decision if whole-file processing is unsafe.

This task addresses intent debt by reconstructing rationale and making the next decision auditable, rather than inventing a reason for existing code.

Check your work

  • Collects multiple relevant evidence types
  • Keeps hypotheses distinct from findings
  • Records tradeoffs and a verification plan
