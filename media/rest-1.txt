Serialization and references

Two maintenance tickets refer to the same building, and that building record refers to its active tickets. Naively nesting the entire building inside each ticket duplicates data. Following the building’s ticket references recursively can also create an endless cycle. The in-memory structure is a graph, while ordinary nested JSON values form a tree. Serialization must decide how to represent identity and relationships instead of blindly walking every pointer. One representation emits building B9 once, emits tickets T1 and T2 once, and links each ticket with buildingId B9. The client resolves those identifiers using the agreed response structure or additional API requests. This reduces duplication but requires a rule for missing references and for when related objects become available. Also distinguish text length from byte length: a title containing accented characters can occupy more UTF-8 bytes than its character count. Schema choices, reference rules and encoding all belong to the data exchange contract.

Choosing a protocol

The maintenance team supports a browser dashboard and an internal batch client. It first lists requirements: available client libraries, message sizes, streaming needs, debugging tools and expected compatibility. A familiar HTTP and JSON interface may make integration easy, while a schema-driven binary representation may be useful for another workload. The decision should compare complete systems under realistic requests, not assume that a smaller encoded message automatically makes the service faster. Keep the design layers visible. REST describes architectural constraints, HTTP defines protocol semantics, and JSON or Protocol Buffers encode data. An RPC framework supplies another set of conventions and tools; binary serialization can still travel over HTTP, as in common gRPC deployments. Reusing HTTP infrastructure also means respecting its caching and retry rules. Before changing formats, measure where time is spent: if most latency is a database wait, saving a few bytes may have little effect. Select an interface that meets the operational and compatibility needs you actually have.
