1. Signing-key rotation without accepting strangers

An identity provider rotates from signing key K1 to K2. A reporting service caches the provider’s trusted verification keys and has not refreshed them, so valid K2 tokens fail. An engineer suggests reading an arbitrary key URL from each token header and fetching that key whenever verification fails. Which response restores rotation support without allowing a token sender to choose its own trust authority?

  1. Fetch any URL the token advertises and trust its result.
  2. Disable signature checks until the next deployment.
  3. Refresh through the configured trusted issuer and retain normal claim validation.
  4. Accept unknown keys if the token has a plausible username.
