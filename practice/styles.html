State assumptions and show your reasoning. For design tasks, more than one solution may be valid; justify the tradeoffs.

1. Interpreting a workflow language

A laboratory application lets technicians save experiment recipes in a small language with variables, conditional branches and repeat-until steps. At runtime an execution engine reads the recipe, maintains variable values and chooses the next operation. Hardware adapters perform permitted instrument actions. Which architectural description best explains the recipe-execution core, without claiming that the entire application has only one style?

  1. Pure pipe and filter because the recipe has more than one step.
  2. Interpreter/virtual-machine style because an engine evaluates a program representation.
  3. Peer-to-peer because many technicians author recipes.
  4. Repository style alone because recipes can be saved.
