HTTP as an API contract

A maintenance service exposes GET /tickets/731. A successful response includes a ticket identifier, a status and an estimated duration. The JSON shape alone is insufficient: clients need to know whether duration means minutes or seconds, whether a missing estimate is null or omitted, and what happens when a ticket is unavailable. An API contract therefore includes meaning and failure behavior as well as a syntactically valid example. Choose the method before inventing an endpoint name. A read should not close the ticket as a side effect. A replacement request to a known ticket target differs from submitting a new work request for the service to process. Document authorization failures and absent resources so clients can react appropriately. Use HTTPS for transport protection, and avoid placing access tokens in example query strings that might appear in logs. These decisions help separate an interoperable service boundary from a collection of loosely specified network calls.


Retries and resource identity

A client submits a repair request and loses its connection before receiving the response. It cannot tell whether the server committed the work. Retrying is therefore an uncertainty problem, not proof that the first attempt failed. A stable target helps: repeating a request to set ticket 731 to the same intended state can be designed to have the same intended effect as one attempt. That does not require identical response bytes or status codes. Contrast this with an operation that closes whichever ticket is currently oldest. After the first success, a retry could close a different ticket. The resource identity moves, so repetition changes the intended effect. Use an explicit ticket identifier for that operation. For creation through POST, define a deduplication mechanism if retries must not create another request. PUT and DELETE have idempotent method semantics; POST and PATCH are not generally guaranteed idempotent. The implementation must honor the chosen contract rather than relying on the method name to repair unsafe behavior.
