Push notifications and connected clients
Part 1 • Synthetic narration

Why the server cannot simply call the phone

A building maintenance app should alert a resident when a repair appointment changes. The scheduling server knows the resident's account, but that knowledge does not give it a reachable network endpoint on the resident's phone. The phone may change networks, sit behind address translation or have its application suspended. Treating the phone as an ordinary public HTTP server leaves those constraints unexplained, even if the notification payload is only a few bytes. Instead, the device or platform establishes an outbound delivery path that the backend can use indirectly. Now consider the phone being offline when the appointment changes twice. Decide whether to retain both changes, replace the first with the latest state, or simply notify the app to refresh. This is a product-level delivery policy, not a detail solved by opening a socket. Keep the authoritative appointment in durable storage so that reconnecting clients can recover their current state even when a notification never arrives.


Registration and mobile delivery

A library app user signs in on a phone and a tablet. Each installation registers for platform notifications and sends its current provider-issued routing token to the authenticated backend. The backend associates both installations with the account. When a reserved book becomes ready, the notification service resolves the account to eligible installations and submits delivery requests. The account identifies the person; the tokens identify destinations through the platform's delivery mechanism. Now uninstall and reinstall the phone app. Its routing information may change, while the person's account remains the same. Registration updates and invalid-token cleanup are therefore part of normal operation. Logging out also requires a policy that prevents the next device user from receiving the previous user's private notifications. Provider acceptance only says a delivery request entered that provider's process; it does not prove the message was displayed or read. A notification can prompt a fresh authorized read of the library record instead of carrying all sensitive details itself.
